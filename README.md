# 烦恼雷达

从爬取的内容和评论中整理问题，寻找值得验证的实物产品机会。当前版本为本地运行的原型，AI 分析结果只是待核查的假设。

## 运行与导入

需要 Node.js 18 或更新版本。Windows 双击 `启动烦恼雷达.cmd`，或在项目目录运行 `node serve.js`，打开 http://127.0.0.1:4174。

在“导入数据”选择内容文件和评论文件（JSON、JSONL 或 CSV），或使用本机 SQLite。SQLite 接口沿用原项目的固定路径 `D:/MediaCrawler-Fork-Test/database/sqlite_tables.db` 和对应 Python 虚拟环境，其他环境需修改 `serve.js` 或使用文件导入。导入后可在“具体问题”中手动归并、拆分、追溯证据和记录验证。

## 实物产品机会

1. 导入数据后打开“实物产品机会”。默认选择本地 Ollama 模式。安装 Ollama 并运行 `ollama pull qwen3.5:9b` 下载模型，保持 Ollama 服务运行。默认模型名为 `qwen3.5:9b`，可改为已经安装的其他模型。本地模式通过本机 `127.0.0.1:11434` 分析，不调用在线分析接口、不需要密钥。默认每批 5 条，长文会截断；首次加载或 CPU 推理可能较慢。
2. 如选择在线 AI 模式，填写兼容 Chat Completions 的服务商 HTTPS 完整地址、模型名称和 API 密钥。密钥只保存在当前页面输入框，刷新后清除；请勿提交到 Git 仓库。在线模式和本地模式使用同一个机会库。
3. 选择起始序号和每批数量（最多 20 条），点击“预览本批原文”。每条截取前 1200 字符，列表按内容、评论顺序排列，不保证覆盖全部原文。
4. 点击分析。在线模式会先要求确认，再将文本和分析指令发送到服务商，可能产生费用；不单独发送作者、原帖 URL 或点赞字段，但原文本身可能含个人信息。本地模式则只将数据发送到本机 Ollama。
5. 查看候选机会和原文证据。系统检查引用是否在送给模型的原文中逐字出现，无法核对的引用会被丢弃。**引用存在不代表推断准确，也不代表问题已验证。**
6. 修改并保存判断。继续分析下一批时调整起始序号；同一批重复分析可能生成重复机会，需人工删除。刷新页面后如需继续分析，需重新导入原始数据。

AI 可能漏掉问题、误解上下文或提出不合适的实物方案。没有证据支撑时应标记未知，结合访谈、竞品和样品测试验证。API 地址、模型、密钥需用户自行向服务商获取。本项目未内置付费服务或密钥。

“具体问题”和“实物产品机会”分别保存在当前浏览器的本地存储中，各自提供导出和恢复备份。清除浏览器数据或更换浏览器可能导致记录丢失，请定期备份；备份包含原文，应妥善保管。原来的主题机会分仅反映当前导入样本中的讨论信号，不代表市场规模或购买意愿。
